# 마찰전기 시뮬레이션 제작 과정 정리

중학교 과학 "마찰 전기" 단원을 눈으로 확인하는 웹 시뮬레이션을 만든 과정을 순서대로 정리한 문서입니다. 다음 시뮬레이션을 만들 때 같은 흐름을 재사용하기 위한 기록이기도 합니다.

- 배포: https://friction-electricity.vercel.app
- 저장소: https://github.com/mrdoolee/science-simulation-project (공개, `main` push 시 Vercel 자동 배포)
- 위치: `friction-electricity/` (정적 사이트, 빌드 도구 없음)

## 1. 한눈에 보는 타임라인

| 단계 | 요청 | 결과 |
|---|---|---|
| 0 | 프롬프트 다듬기 | 교과서 그림(마찰 전후 전자 이동)을 기준으로 요구사항을 정리하고, 빠진 정보(대상, 배포, 정전기 인력)를 확정 |
| 1 | 풍선-털가죽 시뮬레이션 | 왼쪽 드래그 화면 + 오른쪽 전자 이동 화면. GitHub repo 생성, Vercel 배포 |
| 2 | 교과서 탐구 활동 추가 | 상단 메뉴 탭 도입. 실험 1(마찰 전기 현상 관찰하기)을 신규 추가, 기존은 실험 2로 이동 |
| 3 | 양성자·전자 표시 | 오른쪽 패널 모든 장면에서 (+)와 (−)를 함께 표시 |
| 4 | 개념 오류 수정 | 양성자는 고정, 전자만 이동. 무작위 배치를 격자 배치로 교체 |
| 5 | 애니메이션·배치 다듬기 | 실험 1 전자 이동 애니메이션, 단계별 좌우 배치 교체, 미사용 물체 비활성화 |
| 6 | 제작자 크레딧 | 푸터 문구와 안내 모달 |
| 7 | 하네스 구성 | `CLAUDE.md`, 문법 검사 훅, 이 문서 |

## 2. 단계별 상세

### 0. 요구사항 정리
- 처음 요청은 "풍선과 털가죽을 문지르는 화면(왼쪽)"과 "전자가 이동해 대전되는 모습(오른쪽)"이었습니다.
- 확인한 사항: 대상은 중학생, UI는 한국어, 배포는 Vercel, GitHub repo 생성, 마찰 후 정전기 인력(털가죽, 머리카락)도 포함.
- 교과서 그림은 "수건"으로 되어 있었지만 요청이 "털가죽"이어서 털가죽으로 통일했습니다.

### 1. 첫 버전 (풍선과 털가죽)
- 구조: `index.html` + `style.css` + `main.js`. 바닐라 JS, Canvas(왼쪽) + SVG(오른쪽).
- 왼쪽: 풍선을 드래그해 털가죽 위에서 문지르면 마찰량이 오르고, 마찰량에 비례해 전자가 이동합니다. 놓은 풍선은 털가죽에 끌려가 붙습니다.
- 오른쪽 탭: ① 대전 과정(마찰 전, 중, 후) ② 털가죽에 끌림 ③ 머리카락에 끌림.
- 인력 세기는 순전하량에 비례하고 거리에 반비례하며, 전하는 항상 보존됩니다(합 0).
- 디자인은 참고 사이트(https://ionformation.vercel.app/)에서 색, 패널, 버튼 톤을 가져왔습니다. 전자(−)는 초록, 양성자(+)는 빨강입니다.
- 배포 순서: 로컬 검증 → git init → GitHub repo(공개) → Vercel 프로젝트 연결(Root Directory `friction-electricity`) → 배포 URL 확인.

### 2. 실험 1 추가 (마찰 전기 현상 관찰하기)
- 교과서 탐구 활동: 면장갑으로 고무풍선 2개를 문지른 뒤 (2) 풍선끼리 가까이, (3) 장갑을 풍선에 가까이 했을 때의 움직임 관찰.
- 상단 메뉴 탭으로 두 실험을 나눴습니다. 실험 1이 기본 탭입니다.
- 단계 1~3은 순서 제한 없이 자유롭게 이동합니다.
- 물리 모델: 스탠드에 매달린 초록 풍선을 진자로 표현하고, 힘 ∝ (전하 곱)/거리. 같은 부호면 척력, 다른 부호면 인력.
- 관찰 기록 카드: 과정 2(멀어짐), 과정 3(다가옴)을 관찰하면 체크됩니다.

### 3~4. 오른쪽 패널의 개념 정확성
사용자 피드백으로 세 번에 걸쳐 고친 부분입니다.

1. 양성자와 전자가 모두 보이지 않던 장면(실험 1 전체, 실험 2 ②·③)을 (+)와 (−)를 함께 그리도록 수정.
2. 머리카락 유도에서 양성자가 움직이는 것처럼 보이던 오류 수정. 양성자는 제자리, 전자만 풍선 반대쪽으로 이동. 설명 문구도 "(+)가 끌려온다"에서 수정.
3. 안쪽 고리 = 양성자, 바깥 고리 = 전자 배열이 "양성자는 안, 전자는 밖"이라는 오개념을 줄 수 있어 무작위 배치로 바꿨다가, 뭉쳐 보여서 `+ − + −` 격자로 최종 교체.

### 5. 애니메이션과 단계별 배치
- 실험 1 · 문지르기에서도 전자가 장갑 → 풍선으로 곡선 이동하는 애니메이션 추가(실험 2와 동일한 방식).
- 3단계 오른쪽 패널은 왼쪽 면장갑, 오른쪽 초록 풍선으로 교체.
- 2·3단계에서 쓰지 않는 물체는 왼쪽 아래로 치우고, 흐리게 보이며 조작과 힘이 비활성화됩니다. (빨간 풍선 때문에 "밀어내요"가 뜨던 간섭 해결)
- 머리카락 유도: 전자가 원 가장자리 호로 크게 이동하고, 풍선이 붙기 전에 이동이 끝나도록 인력이 약할 때부터 움직입니다.

### 6. 제작자 크레딧
- 푸터: `© 2026 Designed & Developed by 두리쌤. All rights reserved.` ("두리쌤"만 클릭 가능)
- 모달: 이용 조건 카드 + 문의 카드(Instagram, Blog 새 탭 링크).
- 닫기: ✕, 배경 클릭, ESC. 열려 있는 동안 body 스크롤 잠금, `role="dialog"`, `aria-modal`, 포커스 가두기.
- 모달은 표시 전용이라 시뮬레이션 상태를 건드리지 않습니다.

## 3. 핵심 설계 결정

- **정적 사이트 고정**: 프레임워크나 번들러 없이 `index.html`, `style.css`, JS 파일로 구성. 배포와 유지보수가 단순합니다.
- **한 저장소, 시뮬레이션마다 폴더**: 루트가 repo이고 각 시뮬레이션은 독립 폴더. Vercel은 폴더별 프로젝트로 배포합니다.
- **공용 도우미 재사용**: 실험 1(`observe.js`)은 `main.js`의 `el`, `chargeMark`, `place`, `createCharges` 등을 그대로 씁니다.
- **격자 배치**: `latticeSites()`가 원 안에 정사각 격자를 만들고 `(i+j)`의 홀짝으로 (+)와 (−) 자리를 나눕니다. 양성자는 고정 자리, 전자는 자리를 옮깁니다.
- **인력 모델**: 중학생 수준으로 단순화(힘 ∝ 전하/거리). 실제 쿨롱 법칙(거리 제곱 반비례)과 다르다는 점은 문서에만 남기고 화면에서는 "가까울수록 세져요"로 표현.
- **전하 보존**: 장갑의 전하 = 풍선들이 얻은 전자 수. 합이 0이 아니면 `console.assert`가 알립니다.

## 4. 겪은 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 고친 코드가 화면에 안 나옴 | 브라우저가 이전 `main.js`를 캐시 | 확인할 때 `?v=숫자`를 붙이거나 강력 새로고침 |
| 스크린샷이 오래된 화면 | 미리보기 탭이 가려져 `requestAnimationFrame`이 느려짐 | 상태를 코드로 직접 진행시켜 검증하고, 화면은 한 번 더 캡처 |
| 모달 ✕ 버튼이 잘리고 가로 스크롤 | 모달 박스 전체가 `overflow: auto` | 스크롤 영역을 안쪽 `.modal-body`로 분리 |
| `.tab` 선택자 충돌 | 실험 1 단계 탭이 실험 2 `.tab`과 같은 클래스 | 단계 탭은 `.step-tab`으로 분리 |
| `[hidden]`이 안 먹음 | `display: grid`가 `hidden` 속성을 덮어씀 | `[hidden] { display: none !important; }` |
| 훅 테스트가 통과처럼 보임 | 테스트 JSON의 경로가 Windows에서 해석되지 않음 | 슬래시 경로(`C:/...`)로 다시 테스트해서 exit 2 확인 |

## 5. 검증 방법 (매번 같은 순서)

1. `node --check`로 문법 확인 (이제 훅이 자동 실행).
2. 로컬 서버(`.claude/launch.json`의 `friction-electricity`)를 띄워 브라우저에서 확인.
3. 포인터 이벤트를 코드로 발생시켜 드래그, 마찰, 힘, 리셋을 검사.
4. 전하 합 0, 마찰 전 힘 없음, 양성자 위치 고정 같은 불변 조건을 수치로 확인.
5. 375px 폭에서 가로 스크롤 여부, 콘솔 에러 확인.
6. 커밋과 push 후 Vercel 배포 상태(READY)와 라이브 URL을 확인.
